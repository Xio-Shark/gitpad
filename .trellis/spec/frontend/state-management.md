# State Management

> 状态分层与决策标准。

## 分层

| 层 | 内容 | 位置 |
|----|------|------|
| 本地状态 | 组件内部 UI 状态（展开/折叠、面板开关） | `$state` in component |
| 窗口级状态 | Workspace（根路径、文件树数据、打开标签页、Git 面板数据） | `src/lib/state.svelte.ts` 单例 |
| 后端状态 | 文件系统与 git 的真实状态（唯一真相） | Rust 侧 |

## 原则

- **后端是唯一真相源**：文件树、git 状态都以 Rust 侧为准，前端状态只是投影；前端改动 → invoke → 后端返回新状态 → 前端更新投影
- 单窗口 = 单 Workspace：窗口级状态只有一个单例，不需要多实例管理
- 派生状态（如"当前文件是否在 git 改动里"）用 `$derived`，不复制存储
- 不引全局 store 库：Svelte 5 runes + 单例足够，个人工具不要状态管理框架

## 服务端状态（后端数据）

- 文件树按需加载：展开目录时才 invoke `fs_list_dir`（懒加载，大目录不卡）
- 高频请求（watch 事件推送、git 状态刷新）用节流，避免风暴

## 常见错误

- ❌ 前端缓存文件树整个副本再本地过滤——过滤必须后端做（Q6 决策）
- ❌ 多标签页状态散落组件内 —— 打开标签页列表进单例
